
# 时间币和信誉分实时更新 - Product Requirement Document

## Overview
- **Summary**: 修复技能交换平台中时间币和信誉分没有实时更新的问题，确保用户在进行签到、技能交换、发布技能等操作后，页面显示的用户信息能够立即更新
- **Purpose**: 提升用户体验，让用户能够看到自己账户信息的实时变化，避免用户困惑
- **Target Users**: 技能交换平台的所有注册用户

## Goals
- 实现用户状态信息的实时更新机制
- 在签到后立即更新时间币余额
- 在技能交换完成后更新双方的时间币和信誉分
- 在发布第一个技能后奖励时间币并立即显示
- 确保个人中心和导航栏都能同步显示最新数据

## Non-Goals (Out of Scope)
- 不实现 WebSocket 实时通信机制
- 不实现跨设备状态同步
- 不修改数据库表结构
- 不修改后端业务逻辑

## Background & Context
- 当前系统中，用户的时间币和信誉分通过 localStorage 和 Pinia store 进行管理
- 当用户进行签到、发布技能、完成交换等操作后，数据会在后端更新，但前端不会自动刷新显示
- 用户需要重新登录或刷新页面才能看到更新后的信息

## Functional Requirements
- **FR-1**: 签到成功后立即更新时间币余额和连续签到天数显示
- **FR-2**: 技能交换完成后，更新双方的时间币和信誉分
- **FR-3**: 发布第一个技能后，立即显示奖励的时间币
- **FR-4**: 在用户执行任何更新用户状态的操作后，重新获取并更新用户信息
- **FR-5**: 确保个人中心、导航栏等所有显示用户信息的地方都能同步更新

## Non-Functional Requirements
- **NFR-1**: 状态更新应在 100ms 内完成
- **NFR-2**: 不应该影响用户操作体验
- **NFR-3**: 代码变更应该最小化，不引入新的复杂依赖

## Constraints
- **Technical**: 使用现有的 Vue 3 + Pinia + Axios 技术栈
- **Business**: 不修改后端 API，只优化前端状态管理
- **Dependencies**: 依赖后端现有的用户信息获取接口

## Assumptions
- 后端 API `/api/user/current` 能够返回最新的用户信息
- 所有更新用户状态的操作都会正确调用后端 API
- 后端返回的数据格式保持一致

## Acceptance Criteria

### AC-1: 签到后时间币实时更新
- **Given**: 用户已登录，且今日未签到
- **When**: 用户点击签到按钮并成功签到
- **Then**: 页面显示的时间币余额立即增加，连续签到天数更新
- **Verification**: `human-judgment`
- **Notes**: 需要验证个人中心、导航栏等所有显示时间币的地方

### AC-2: 发布技能后奖励时间币实时显示
- **Given**: 用户首次发布技能
- **When**: 技能发布成功
- **Then**: 用户的时间币余额立即显示奖励后的数值
- **Verification**: `human-judgment`

### AC-3: 完成技能交换后数据更新
- **Given**: 用户完成一次技能交换
- **When**: 交换状态变为完成
- **Then**: 双方的时间币和信誉分都相应更新并显示
- **Verification**: `human-judgment`

### AC-4: 修改个人信息后立即更新
- **Given**: 用户修改了个人信息
- **When**: 修改成功保存
- **Then**: 页面显示的用户信息立即更新
- **Verification**: `human-judgment`
